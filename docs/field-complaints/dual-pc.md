# Field complaints: stream-PC / second-PC (dual-PC) setups

Date: 2026-11-06. Scope: capture card to stream PC, audio routing and sync between PCs, NDI, clock drift, USB bandwidth, obs-websocket across PCs, driver/permission issues. Reference setup: Sony a6000 -> Elgato Cam Link -> stream PC, game on a separate PC. Not repeated here: camera.md, mic-audio.md, stream-obs.md rows (single-PC encoder/network/audio).

## Method and limits
- Web search (summaries) plus two direct fetches (obs-websocket README, Elgato help titles). Most OBS forum threads were read only through search snippets, so quotes are paraphrased. Reddit not reachable. No Elgato help article body was read: only titles and snippet claims.
- Labels: **FACT** = stated by a vendor/official doc page (read or snippet). **REPORT** = user report in a forum thread, not confirmed by staff. **OPINION** = guide author or my judgement. **UNVERIFIED** = no source.
- Many drift threads are 2015-2020 (OBS 19-27, HD60 Pro era). Their relevance to Cam Link 4K on OBS 30+ is **UNVERIFIED**.
- "In Setup Coach today?" checked by grep of `core/src` (no `4455`, `127.0.0.1` or `localhost` string found: the OBS websocket host is probably configured elsewhere or hardcoded differently; **unverified**, check `core/src/system/obs_*` before building), and by the catalog in stream-obs.md.

## Key structural fact
Dual-PC has two OBS instances and two clocks. Game PC clock (game audio, maybe its own OBS/NDI sender) and stream PC clock (Cam Link video, mic, encode). Anything that crosses the boundary (HDMI capture, NDI, audio cable) has its own latency and clock. This is the root of most complaints below (OPINION, consistent with the threads).

## What Setup Coach can detect on ONE PC (which PC matters)
- **On the stream PC (best single target):** all of rows 1, 2, 3, 4 (setup part), 8, 9, 12, plus existing stream.* health. Everything involving the capture device, OBS scene config and USB tree lives here, so the app already covers the right machine if the user installs it there. The Cam Link and a6000 are on this PC.
- **On the game PC:** only GPU/CPU headroom, game fps, NDI sender load (row 7), audio route to the stream PC (row 8).
- **Remote-only:** obs-websocket to the other PC is possible in principle (row 10) but unproven in the code.

## What it needs to run on both
1. A host/port/password field for the OBS websocket (not localhost only) with clear connect errors (refused vs auth vs timeout).
2. A role per machine (game PC / stream PC) chosen once, so findings are routed to the right machine and the other PC's stats are not misread.
3. A way to link the two instances: either the app installed on both with a pairing code, or one app talking to the second OBS over websocket. A link-speed check needs both NIC speeds; a drift test needs a signal produced on one PC and measured on the other (beep out, beep in).
4. No AI processing is involved anywhere here, so the product rules are not affected. Opening apps for the user and detecting completion (the coaching rule) works across PCs only if paired.

## Ranked: gaps to build next
Ranked by (how often it appears in sources) x (detectable on one PC) x (fixable without hardware purchase).

1. **Capture device check (rows 1, 2, 12).** Identify Cam Link, its USB controller generation and link speed, hub in path, sharing with other heavy devices, negotiated mode vs camera output; give the Elgato-documented fixes first (USB 3.0 port, no hub). Runs on the stream PC with no new infrastructure.
2. **Sony HDMI cadence check (row 3).** Detect 50 vs 59.94 fps, interlacing and overlay/info icons from the live frames; coach NTSC, 1080p60, info display off. Per-camera menu labels need the a6000 manual: **unverified**.
3. **Capture-audio configuration check (rows 4, 8).** Flag the video device's embedded audio enabled together with a separate audio source, or no game audio path at all; recommend a separate audio device or a single mixer path.
4. **Drift test, not just offset (rows 4, 5, 9).** Clap/beep at start, again later, report slope in ms per 10 min; only suggest a fixed offset when the slope is about zero. This is the one feature that solves the "toggle the source every hour" complaint class honestly.
5. **Remote websocket connect with good errors (row 10).** Host field, password, TCP-vs-auth diagnosis, firewall and network profile hint. Prerequisite for anything cross-PC.
6. **PC role + stats routing (row 11, 7).** Role choice, and warning when stream health is read from the wrong PC.
7. **Inter-PC link check (row 6).** NIC speed, Wi-Fi, utilisation; only relevant when NDI is used, so low priority for a capture-card setup.
8. **NDI source settings audit (row 5).** Sync mode and offsets from scene JSON; low value without a drift measurement and no confirmed best setting.
9. **Cross-PC sample rate / clock (row 13).** Needs the app on both; evidence thin.

## Honest bottom line (OPINION)
Dual-PC with a capture card is mostly a hardware-path problem (USB, HDMI mode, audio route) that Setup Coach can check on the stream PC alone. NDI-specific problems (drift, bandwidth) are real in forums but have no confirmed root cause, so Setup Coach should measure rather than prescribe. Most complaints disappear when audio is taken from one clock source.
